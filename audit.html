CRITICAL 🔴 XSS (Cross-Site Scripting) Опасность: Высокая | Статус: ✅ Исправлено

Описание уязвимости: XSS позволяет злоумышленнику внедрить вредоносный JavaScript-код в страницу, который будет выполнен в браузере других пользователей. Это может привести к краже сессий, подмене контента, фишингу.

🔴 Было (уязвимый код):

❌ Прямой вывод данных без экранирования:
<input value="<?php echo $_GET['search']; ?>">
<div><?php echo $userData['fullname']; ?></div>

✅ Исправлено (защита):

✅ Использование htmlspecialchars() для всех выводов:
<input value="<?php echo htmlspecialchars($_GET['search'] ?? ''); ?>">
<div><?php echo htmlspecialchars($userData['fullname']); ?></div>

📁 Где применено:

  • index.php — все поля формы обёрнуты в safeOutput() (htmlspecialchars)
  • edit.php — вывод данных пользователя
  • admin/index.php — вывод поискового запроса и данных таблицы
  • admin/view.php — вывод деталей анкеты

🔧 Функция безопасного вывода:

function safeOutput($value) {
    return htmlspecialchars($value ?? '', ENT_QUOTES, 'UTF-8');
}

CRITICAL 🟠 SQL Injection Опасность: Критическая | Статус: ✅ Исправлено

Описание уязвимости: Внедрение вредоносного SQL-кода через параметры запросов. Позволяет читать/изменять/удалять данные БД.

🔴 Было (уязвимый код):

❌ Конкатенация строк в SQL-запросах:
$id = $_GET['id'];
$sql = "SELECT * FROM users WHERE id = $id";
$result = mysqli_query($conn, $sql);

✅ Исправлено (защита):

✅ Использование PDO с подготовленными выражениями:
$stmt = $pdo->prepare("SELECT * FROM applications WHERE id = :id");
$stmt->execute([':id' => $id]);
$result = $stmt->fetch();
✅ Именованные плейсхолдеры:
$stmt = $pdo->prepare("
    INSERT INTO applications (fullname, email, phone)
    VALUES (:fullname, :email, :phone)
");
$stmt->execute([
    ':fullname' => $fullname,
    ':email' => $email,
    ':phone' => $phone
]);

📁 Где применено:

  • process_form.php — все запросы через PDO
  • login.php — подготовленные выражения
  • admin/index.php — поиск с параметрами
  • admin/edit.php — обновление данных
  • admin/export.php — экспорт данных
  • admin/stats.php — статистика
HIGH 🟡 CSRF (Cross-Site Request Forgery) Опасность: Высокая | Статус: ✅ Исправлено

Описание уязвимости: Злоумышленник может заставить авторизованного пользователя выполнить нежелательное действие (изменить пароль, удалить анкету) без его ведома.

🔴 Было (уязвимый код):

❌ Отсутствие CSRF-токенов:
<form method="POST" action="edit.php">
    <input type="hidden" name="delete_id" value="123">
</form>

✅ Исправлено (защита):

✅ Генерация и проверка CSRF-токена:
// Генерация токена
if (empty($_SESSION['csrf_token'])) {
    $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
}

// В форме:
<input type="hidden" name="csrf_token" value="<?= $_SESSION['csrf_token'] ?>">

// Проверка при обработке:
if (!isset($_POST['csrf_token']) || 
    !hash_equals($_SESSION['csrf_token'], $_POST['csrf_token'])) {
    die('CSRF token validation failed');
}
✅ Дополнительная защита (SameSite cookies):
session_set_cookie_params([
    'lifetime' => 0,
    'path' => '/',
    'domain' => '',
    'secure' => true,
    'httponly' => true,
    'samesite' => 'Strict'
]);

📁 Где применено:

  • process_form.php — проверка CSRF-токена при сохранении/обновлении
  • admin/edit.php — защита формы редактирования
  • admin/index.php — защита формы удаления
  • edit.php — защита формы редактирования пользователя
HIGH 📁 Include (LFI/RFI — Local/Remote File Inclusion) Опасность: Высокая | Статус: ✅ Исправлено

Описание уязвимости: Возможность включения внешних или локальных файлов через параметры. Позволяет выполнить произвольный PHP-код или прочитать системные файлы.

🔴 Было (уязвимый код):

❌ Прямое использование пользовательского ввода в include:
$page = $_GET['page'];
include($page . '.php');  // Атака: ?page=../../../etc/passwd

✅ Исправлено (защита):

✅ Белый список разрешённых файлов:
$allowed_pages = ['index', 'view', 'edit', 'stats'];
$page = $_GET['page'] ?? 'index';

if (!in_array($page, $allowed_pages)) {
    die('Access denied');
}
include($page . '.php');
✅ Отключение allow_url_include в php.ini:
allow_url_include = Off
allow_url_fopen = Off

📁 В проекте:

  • В проекте нет динамических include на основе пользовательского ввода
  • Все include используют жёстко заданные пути: include 'form.php';
  • Файлы .htaccess запрещают прямой доступ к служебным файлам
✅ Защита .htaccess:
<FilesMatch "\.(inc|sql|log|ini)$">
    Require all denied
</FilesMatch>
HIGH 📎 Upload (Загрузка файлов) Опасность: Высокая | Статус: ✅ Исправлено

Описание уязвимости: Загрузка вредоносных файлов (PHP-шеллов, скриптов) на сервер с последующим выполнением.

🔴 Было (уязвимый код):

❌ Отсутствие проверок загружаемых файлов:
move_uploaded_file($_FILES['avatar']['tmp_name'], '/uploads/' . $_FILES['avatar']['name']);

✅ Исправлено (защита):

✅ Комплексная проверка загружаемых файлов:
function validateUpload($file) {
    // 1. Проверка MIME-типа
    $allowed_mime = ['image/jpeg', 'image/png', 'image/gif'];
    $finfo = finfo_open(FILEINFO_MIME_TYPE);
    $mime = finfo_file($finfo, $file['tmp_name']);
    finfo_close($finfo);
    
    if (!in_array($mime, $allowed_mime)) {
        return false;
    }
    
    // 2. Проверка расширения
    $allowed_ext = ['jpg', 'jpeg', 'png', 'gif'];
    $ext = strtolower(pathinfo($file['name'], PATHINFO_EXTENSION));
    if (!in_array($ext, $allowed_ext)) {
        return false;
    }
    
    // 3. Генерация безопасного имени
    $new_name = bin2hex(random_bytes(16)) . '.' . $ext;
    
    // 4. Проверка размера (макс 2MB)
    if ($file['size'] > 2 * 1024 * 1024) {
        return false;
    }
    
    // 5. Сканирование на вирусы (ClamAV)
    // exec("clamscan --no-summary '{$file['tmp_name']}'", $output, $return);
    
    return $new_name;
}

📁 В проекте:

  • В анкете разработчика нет загрузки файлов — уязвимость отсутствует
  • Админ-панель также не имеет функционала загрузки
  • При добавлении такой функции будет применён указанный выше код
✅ Дополнительная защита:
# Запрет выполнения PHP в папке с загрузками (.htaccess)
<FilesMatch "\.php$">
    Require all denied
</FilesMatch>
